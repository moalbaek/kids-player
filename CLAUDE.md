# CLAUDE.md

Project memory for working on Kids Player: an ESP32-S3 touchscreen that browses Spotify and plays on Sonos.
Read README.md for the user-facing overview. This file is what you need to change the code safely.

## Layout

- `firmware/` ESP-IDF 5.5 project, one source tree, two boards chosen by Kconfig (`CONFIG_KP_BOARD_CUBE` /
  `CONFIG_KP_BOARD_STRIP`, set by `sdkconfig.defaults.<board>`). Board name for OTA paths: `CONFIG_KP_BOARD_NAME`.
- `firmware/main/` all app code. `config.h` holds the Spotify client ID, redirect URI, scopes, limits and
  per-board screen constants.
- `firmware/test/` host unit tests (`sh firmware/test/run.sh`, needs `IDF_PATH` for cJSON). Covers
  `kp_util.c`, `sonos_proto.c`, `spotify_parse.c` with fixtures in `test/fixtures/`.
- `firmware/sim/` desktop renderer: compiles the real `ui.c` against LVGL with stubs and writes PNGs of every
  screen to `sim/out/` (`make -C firmware/sim`). Use it to check any UI change before flashing. Needs a
  firmware build first (for `managed_components/lvgl__lvgl`).
- `docs/` GitHub Pages site (branch main, folder /docs): `index.html` installer page (ESP Web Tools,
  pinned version), `callback.html` Spotify login relay, `flash/` merged images + manifests, `fw/<board>/`
  OTA image + `version.json`. Generated by `firmware/release.sh`; never edit `flash/` or `fw/` by hand.

## Build, test, release

```sh
. $HOME/esp/esp-idf/export.sh
cd firmware
idf.py -B build_<board> -D SDKCONFIG=build_<board>/sdkconfig \
       -D SDKCONFIG_DEFAULTS="sdkconfig.defaults;sdkconfig.defaults.<board>" build
sh test/run.sh
make -C sim
```

- An existing `build_<board>/sdkconfig` wins over edited `sdkconfig.defaults*`. Delete it (or edit it too)
  when you change defaults.
- Release: bump `PROJECT_VER` in `firmware/CMakeLists.txt`, run `firmware/release.sh`, commit `docs/`, push.
  Players compare `docs/fw/<board>/version.json` with their own version (`kp_version_cmp`) and update.
  A new image is marked valid only after 30 s online; otherwise the bootloader rolls back on restart.
- Keep both boards building without warnings in `main/`.

## Architecture rules

- **The app task owns the flow and all network calls** (`app_main.c`). UI callbacks, buttons and the web
  server only post commands (`app_post`, `app_post_search`) through a queue. Don't call Spotify/Sonos from
  the LVGL task or the HTTP server task (exception: `/callback` finishes the login token exchange).
- **LVGL is not thread safe.** Every `ui_*` function takes `board_lock(-1)` itself. Code in LVGL event
  callbacks already holds the lock. Lock order is LVGL lock, then the images mutex, never the reverse.
  On the cube, `board_lock` calls `esp_lv_adapter_lock` directly: `bsp_display_lock(0)` does not wait and
  its bool return is inverted.
- **The UI copies what it shows** (ids, cover URLs, label text), so the app can replace its lists any time.
- **Lists are double-buffered** (`s_home/_spare`, `s_tracks/_spare`): load into the spare, swap on success.
- **Taps carry a token.** `CMD_PLAY` includes `s_list_token`; bump it whenever the song list on screen
  changes so stale taps are ignored.
- One entry type for everything on screen: `sp_entry_t` (`kind` = playlist, album, track, liked, search).
- Settings live in NVS namespace `kp` (`settings.c`); add new keys there with a board-specific default.
- Internal RAM is tight (Wi-Fi, TLS, DMA). Big buffers go to PSRAM (`heap_caps_*(…, MALLOC_CAP_SPIRAM)`).
  LVGL code is kept out of IRAM on purpose. Main task stack is 16 KB because TLS runs on it.

## Spotify Web API (Development Mode, rules from February 2026)

- Auth: authorization code + PKCE (S256), no client secret, ever. State is `<32-hex nonce>~<player-ip>`;
  `docs/callback.html` forwards only to private IPv4 addresses. Redirect URI must be HTTPS.
- Scopes: `playlist-read-private playlist-read-collaborative user-library-read`. Changing scopes means
  users must log in again.
- Playlist songs: `GET /playlists/{id}/items`; the field is `item` (was `track`); parser accepts both and
  the request falls back to no `fields` filter. Songs are only returned for playlists the user owns or
  collaborates on: `can_list` is false for others, and tapping them plays the container directly.
- Search: `limit` max 10 per type. Batch endpoints (`GET /tracks?ids=`, `/albums?ids=`), artist top tracks
  and other users' playlists are gone. Still available: `/me`, `/me/playlists`, `/me/albums`, `/me/tracks`,
  `/albums/{id}`, `/albums/{id}/tracks`, `/search`.
- Refresh tokens expire about 6 months after login (`invalid_grant`): clear the token and show the login QR.
- At most 5 users per app; the owner needs Premium.

## Sonos (local UPnP, port 1400)

- Spotify Connect Web API can't control Sonos; everything goes through UPnP SOAP to the group coordinator
  (found via `ZoneGroupTopology/GetZoneGroupState`, cached 30 s).
- Play = `RemoveAllTracksFromQueue`, `AddURIToQueue`, `SetAVTransportURI x-rincon-queue:<uid>#0`,
  `Seek TRACK_NR`, `Play`. After seeking, `GetPositionInfo` checks the song; if it differs, `Browse Q:0`
  finds its real position (`sonos_queue_position`).
- URIs (`sonos_proto.c`): playlist `x-rincon-cpcontainer:1006206cspotify%3aplaylist%3a<id>`, album
  `x-rincon-cpcontainer:1004206cspotify%3aalbum%3a<id>`, song
  `x-sonos-spotify:spotify%3atrack%3a<id>?sid=<sid>&flags=8224&sn=<sn>` (bare `spotify%3atrack%3a<id>` if
  sn unknown). DIDL `desc` = `SA_RINCON<type>_X_#Svc<type>-0-Token`, type = sid*256+7.
- Confirmed on the owner's system: sid 9, sn 5, type 2311, playlist container + seek works. Album
  containers and single songs follow SoCo's share-link values but are not yet confirmed on hardware.
- Discovery: SSDP for `ZonePlayer`, falling back to a saved/typed speaker IP (for VLAN setups).

## Hardware notes

- Cube (Waveshare ESP32-S3-Touch-AMOLED-2.16): BSP `waveshare/esp32_s3_touch_amoled_2_16` + esp_lvgl_adapter.
  KEY3 = GPIO18, BOOT = GPIO0. AXP2101 at I2C 0x34 (shared BSP bus): power-key IRQ status reg 0x49
  (bit3 short, bit2 long), battery % at 0xA4, power off = 0x10 bit0.
- Strip (Waveshare ESP32-S3-Touch-LCD-3.49 **V2**; V1 has different pins): AXS15231B QSPI on SPI3
  (CS 9, CLK 10, D0-D3 11-14), 40 MHz, mode 3, own LVGL port with full-frame render rotated 90° (270° if
  `flip`). Backlight PWM GPIO42 is inverted. TCA9554 at 0x20 on I2C 47/48: bit1 backlight, bit5 LCD reset,
  bit6 power hold. Touch on its own I2C (17/18) at 0x3B. BOOT = GPIO0, PWR = GPIO16.
- Unverified on hardware: strip touch orientation, cube button placement (settings have flip/swap options).

## Conventions

- Plain C11, ESP-IDF style, 4-space indent, 120 columns. Comments say why, not what.
- User-facing text is short, plain English; the UI fonts (Nunito, `main/fonts/`) cover Latin-1 so Danish
  letters work. Icons come from the Montserrat fallback (`LV_SYMBOL_*`).
- Never commit secrets. The Spotify client ID is public by design.
